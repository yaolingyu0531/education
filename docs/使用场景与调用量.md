# 使用场景与调用量

> Token 预算不能只按「每条反馈调一次」算。下面把本系统的六类模型调用逐个列清。

| 编号 | 场景 | 触发条件 | 月调用次数 | 单次输入 | 单次输出 | 说明 |
| --- | --- | --- | ---: | ---: | ---: | --- |
| S1 | 单条反馈生成建议 | 每条新反馈 | 1,200 | 2,800 | 150 | 主场景；检索 8 段上下文 |
| S2 | 教师追问与修订 | 约 50% 的建议 | 600 | 1,400 | 200 | 教师问「这条依据在哪」「换个说法」 |
| S3 | 企业导师填写助手 | 约 30% 的反馈 | 360 | 800 | 300 | 把口语描述整理成「岗位任务＋行为实例」 |
| S4 | 建议合规自检 | 每条建议 | 1,200 | 600 | 100 | 检查是否含敏感属性、是否有实例支撑 |
| S5 | 失败重试与 JSON 修复 | 约 10% 的调用 | 340 | 1,000 | 150 | 模型输出不合规时重跑一次 |
| S6 | 历史回放（一次性） | 项目期内 | 18（摊 5 个月） | 3,500 | 500 | 30 条历史反馈做可行性预演 |

## 为什么主场景按 2,800 token 而不是 1,730

原估算只算了 4 段检索上下文。实际使用中：

1. **检索 8 段**才能覆盖「岗位任务 + 行为实例 + 课程口径 + 验收标准」四类依据，2180 → 2,240 token；
2. **系统提示词加长**：要带角色边界、红线清单、JSON schema，从 350 涨到 400；
3. **观察记录更完整**：企业导师通常给 3～5 条，从 180 涨到 250。

## 月度合计

| 项 | 计算 | 结果 |
| --- | --- | ---: |
| 输入 | 1,200×2,800 + 600×1,400 + 360×800 + 1,200×600 + 340×1,000 + 18×3,500 | **5.61 M** |
| 输出 | 1,200×150 + 600×200 + 360×300 + 1,200×100 + 340×150 + 18×500 | **0.59 M** |
| 合计 | | **6.20 M/月** |

对比原估算（2.26 M/月），**实际调用量约为原来的 2.7 倍**。
