# 案例分析：四笔账

> 07 章。课件给了三个参照案例，这里把它们与本项目逐项对齐，再补一次「报价翻车复盘」。

## 一、四笔账对照

| 维度 | 案例一：电商智能客服 | 案例二：银行网点助手 | 案例三：青禾报销 | **本项目：实习反馈** |
| --- | --- | --- | --- | --- |
| 报价模式 | API 按量 | 私有化项目总价 | 按单测算 | **组合报价** |
| 用量 | 高（日均万次） | 中（网点数千次/日） | 中（2,400 单/月） | **低（1,200 条/月）** |
| 模型成本占比 | 高（30%+） | 低（自建摊销） | 中 | **1.7%（1,200/69,380）** |
| 数据边界 | 可上云 | 不可出内网 | 影像在云、系统在内网 | **个体评价不出校** |
| 主要成本 | Token | 硬件与实施 | 人力与对接 | **人力（60%）＋数据（14%）** |
| 风险点 | 用量超预期 | 验收周期长 | 单据识别率 | **24/30 验收与教师工时基线** |

**一句话**：模型成本占比越低，说明这个项目越「重人力、轻算力」——本项目的钱主要花在人和数据上，Token 只是零头。

## 二、报价翻车复盘：我们自己的五版

课件里「低估 Agent 步数，毛利一夜转负」不是别人的故事，本项目就演了一遍：

| 版本 | 假设 | 结果 | 翻车原因 |
| --- | --- | --- | --- |
| v1 | 1,800 元/人天，模型 6,000/年 | 116,300，账面刚好装进 12 万 | 单价拍脑袋；模型费拍脑袋，一高一低相互掩盖 |
| v2 | 换成 2,450 真实单价 | 150,100，超预算 25% | 单价一修正，前面「刚好」立刻变亏损 |
| v3 | 实习生 990 元/人天 | 74,180 | 人力结构变了，成本腰斩但漏了导师复核风险 |
| v4 | Token 实测后模型费 6,000 → 360 | 68,540 | 模型费高估 20 倍 |
| v5 | 场景扩到 6 类，模型费 360 → 1,200 | 69,380 | 单场景估算法漏了追问、自检、重试 |

**三条教训：**

1. **不要用两个相反方向的错误相互抵消**。v1 里单价偏低、模型费偏高，账面正好，一验就崩。
2. **成本表的每个数字都要能追到一个公式**。追不到的（如 6,000 元模型费）一律标成待验证。
3. **改动要留版本表**。五版并存不是反复，是证据链；老师问「为什么改了五次」，表就是答案。

## 三、如果重来一次

| 动作 | 提前到哪一步 |
| --- | --- |
| 先拿人天测算器算单价 | 报价前第一步（对应练 2） |
| 先列使用场景再算 Token | 写成本表之前（对应练 3） |
| 先确认「谁来做」（实习生/正式） | 报人天之前（决定 v2 与 v3 的差别） |
| 先跑 30 条回放再定价 | 报价前（验证 24/30 是否可达） |

这四条如果一开始就做，五版可以压到两版。
