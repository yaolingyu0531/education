# 案例分析：四笔账（v7 口径）

> 课件三个参照案例 + 本项目现况；末节是报价翻车复盘。

## 一、四笔账对照

| 维度 | 电商智能客服 | 银行网点助手 | 青禾报销 | **本项目** |
| --- | --- | --- | --- | --- |
| 报价模式 | API 按量 | 私有化总价 | 组合报价 | **组合报价** |
| 用量 | 日万级 | 日千级 | 2,000 单/月 | **1,200 条/月** |
| 模型占比 | 30%+ | 低 | 0.3% | **2.2%** |
| 数据边界 | 可上云 | 不出内网 | 混合 | **个体评价不出校** |
| 主要成本 | Token | 硬件 | 人力与对接 | **人力 44.6% ＋ 数据 10.8%** |
| 首年报价 | — | — | 303,562 | **71,940** |
| 回本 | — | — | 7.1 月 | **26.4 月** |
| 风险点 | 用量超预期 | 验收周期 | 识别率 | **24/30 验收与教师工时基线** |

**一句话**：模型占比越低，项目越「重人力、轻算力」；本项目的钱花在人和数据上，Token 是零头。

## 二、报价翻车复盘：我们自己的七版

| 版本 | 假设 | 结果 | 翻车原因 |
| --- | --- | --- | --- |
| v1 | 1,800 元/人天，模型 6,000/年 | 116,300 | 单价与模型费两个方向都拍脑袋，相互掩盖 |
| v2 | 换 2,450 真实单价 | 150,100 | 单价一修正，账面「刚好」变亏损 |
| v3 | 实习生 990 | 74,180 | 人力结构变了，漏算导师复核 |
| v4 | 模型费 6,000 → 360 | 68,540 | 实测 Token 后发现高估 20 倍 |
| v5 | 场景扩 6 类，模型 1,200 | 69,380 | 单场景估算法漏了追问、自检、重试 |
| v6 | 六块 + 风险预留 8%，保本/对外分开 | 85,333 成本 | 按模板重做，成本口径独立 |
| **v7** | **缩到 24 人天试点** | **55,436 / 71,940** | **42 人天版续年高于年收益，客户第二年负收益** |

## 三、三条教训

1. **不要用两个相反方向的错误相互抵消**：v1 的单价偏低、模型费偏高，账面正好，一验就崩。
2. **成本与报价必须分口径**：成本用保本价、报价用对外价，混用会让毛利消失在账里。
3. **改动要留版本表**：七版并存是证据链，不是反复。

## 四、如果重来

| 动作 | 提前到哪一步 |
| --- | --- |
| 先拿人天测算器算单价 | 报价第一步（练 2） |
| 先列使用场景再算 Token | 写成本表之前（练 3） |
| 先确认「谁来做」 | 报人天之前（决定 v2/v3） |
| 先跑 30 条回放 | 定价之前（验 24/30） |
| 先算续年与年收益 | 定范围之前（决定 42 还是 24 人天） |

最后一条是 v6→v7 才学到的：**决定范围的不是成本，是客户第二年的净收益**。
